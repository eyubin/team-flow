# C4-style diagrams

TeamFlow is a **modular monolith**: one Spring Boot process, one PostgreSQL database, one React SPA. Modules are package boundaries, not separately deployed services.

## Level 1 — Context

```mermaid
C4Context
  title TeamFlow — system context

  Person(user, "Team member", "Registers, manages projects and tasks")
  Person(reviewer, "Portfolio reviewer", "Runs demo via Compose or GHCR images")

  System(teamflow, "TeamFlow", "Project and task workflow with roles, audit, and optimistic locking")

  System_Ext(ghcr, "GitHub Container Registry", "Versioned frontend/backend images")
  System_Ext(gha, "GitHub Actions", "CI, SAST/SCA, image scan, release")

  Rel(user, teamflow, "HTTPS / cookies")
  Rel(reviewer, teamflow, "docker compose up")
  Rel(gha, ghcr, "Publish images")
  Rel(reviewer, ghcr, "Pull images (optional)")
```

## Level 2 — Container

```mermaid
C4Container
  title TeamFlow — containers

  Person(user, "User")

  Container_Boundary(browser, "Browser") {
    Container(spa, "Web SPA", "React, TypeScript, Vite", "Login, board, members, history")
  }

  Container_Boundary(compose, "Docker Compose (local / CI)") {
    Container(api, "API", "Java 25, Spring Boot", "REST, authz, JWT cookies, OpenAPI")
    ContainerDb(db, "Database", "PostgreSQL", "users, workspaces, tasks, audit")
  }

  Rel(user, spa, "HTTPS")
  Rel(spa, api, "HTTPS, HttpOnly cookies, CSRF header, /api")
  Rel(api, db, "JDBC, Flyway")
```

Browser never talks to PostgreSQL. JWT payload is not stored in `localStorage`.

## Modular monolith (inside the API)

```mermaid
flowchart LR
  subgraph api [Spring Boot process]
    auth[auth]
    workspace[workspace]
    task[task]
    audit[audit]
    shared[shared]
  end

  auth --> shared
  workspace --> shared
  workspace --> auth
  task --> shared
  task --> workspace
  task --> auth
  audit --> shared
  task --> audit
  workspace --> audit
```

| Module      | Owns                                      |
| ----------- | ----------------------------------------- |
| `auth`      | Users, register/login/refresh/logout, `/me`   |
| `workspace` | Workspaces, members, projects, role checks |
| `task`      | Tasks, comments, list filters              |
| `audit`     | `audit_events` write/query                 |
| `shared`    | Security config, Problem Details, pagination |

Persistence and HTTP DTOs stay inside the owning module. Other modules depend on application services or small published ports, not on JPA entities.
